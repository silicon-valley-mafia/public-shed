## User goal

Prepare a researched development plan for jeetrex17/TDrive issue #186. The desired Activity workflow must support retrying:
- one failed file,
- eligible failed files in one containing folder,
- all eligible failed files in the selected upload batch.

The retry must preserve original source/destination context, avoid resending successful files, detect changed/missing sources, and ask before uploading a changed current version. Work must be split into small developer issues and handed over one at a time.

## Key findings

- Regular flat-file uploads already have a bulk retry action through Review failed files.
- The maintainer clarified in issue #186 that folder uploads lacked this capability; the user confirmed the affected case was a folder with multiple subfolders.
- Draft PR #200 adds same-session desktop folder-import retry, preserving original per-file ParentID and checking source size/modification time/file identity. It excludes extracted temporary archive members and keeps mobile folder retry out of scope.
- PR #200 was open/draft at research time and is the prerequisite baseline; do not duplicate it.
- The draft still uses a bulk review dialog. It does not add individual-file or per-folder Try Again actions.
- The draft rejects changed sources as non-retryable; it does not yet ask whether the current version may be uploaded.
- The frontend currently consumes an entire failed-upload report via a WeakSet. Granular partial retry needs per-file state and stable source identity.
- Existing Activity grouping by relative containing-folder path can support folder-level selection.
- Source paths/retry actions are intentionally session-only; persisted Activity history is display-only. Preserve this privacy/lifecycle boundary.
- Unknown Telegram send outcomes and projection_pending must never be blindly retried. Telegram random_id deduplication is an automatic retry safeguard, not permission to create a new manual upload when the old outcome is unknown.
- Size + modification time + SameFile is a practical low-cost change detector, not cryptographic proof. Full hashing is excluded from the default path and the limitation is documented.
